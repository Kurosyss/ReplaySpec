## Deliverables (12)

### 1. Persistent Investigation Storage
- **Location:** `src/lib/investigations/store.ts` — typed, file-based, Zod-validated
- **Root:** `test-results/investigations/<investigationId>/` with `investigation.json`, `bundle.json`, `frames/*.png`, `spec.json`, `spec-test.ts`
- **Features:** Collision-resistant IDs (`Date.now().toString(36)` + `crypto.randomBytes(4).toString('hex')`), atomic writes (temp + rename), Zod validation on write/read, relative paths only, path traversal prevention (`isValidInvestigationId` regex, `path.resolve` check), missing/malformed/partial record handling, survives dev-server restarts, gitignored `test-results/`.

### 2. Automatic Timestamped Frame Extraction
- **Reused:** `scripts/extract-frames.mjs` → `src/lib/frames/extractor.ts` — `extractFramesFromVideo()` with fixed `ffmpeg -ss -i -vframes 1 -q:v 2` and `ffprobe` args, `shell: false`, no user input, chronological ordering, unique `frame-00-00-8` IDs, 5–6 frames per recording, handles empty/short/missing video, timestamp ordering and duplicate ID checks, extraction errors recorded honestly, never fabricates.
- **Integrated:** `src/lib/runs/runner.ts` now calls `extractFramesFromVideo` after `context.close()` into `test-results/runs/<runId>/frames/` + `manifest.json` for each completed BUG-01 run.

### 3. Real Investigation Creation from Completed Runs
- **API:** `POST /api/investigations` with `CreateSchema { runId }`, validates run exists and `status=completed` with frames, builds `EvidenceBundle` from run's frames (empty postal genuine), validates via `EvidenceBundleSchema`, generates `InvestigationMeta` with `runId`, saves via `saveInvestigation`, copies frames, returns `201` with `id`.
- **API:** `GET /api/investigations` lists persisted (merged with fixture for regression), `GET /api/investigations/[id]` returns `investigation.json` + `bundle.json` + `spec.json`, 404 for missing, no silent substitution (fixture only for `bug-01` fallback, honest not-found for others).
- **UI:** `src/app/investigations/page.tsx` is client component with `fetchInvestigations` + `fetchEligibleRun` + `handleNewInvestigation` (tries `GET /api/runs?recent=1` → `POST /api/investigations`, handles 422 empty state with link to execution, persists `lastRunId` in `localStorage`).

### 4. Dynamic Investigation Listing
- **Location:** `src/app/investigations/page.tsx` — reads from `GET /api/investigations`, merges persisted + fixture (de-dupe by id), shows `frameCount`, `duration`, `verdict`, `updatedAt`, with `VerdictPill` using design tokens.

### 5. Persistent Investigation Detail
- **Location:** `src/app/investigations/[id]/page.tsx` — dynamic client page, fetches `/api/investigations/[id]`, maps `frames/frame-xxx.png` to `/api/investigations/[id]/frames/[file]`, restores `EvidenceBundle` and `InvestigationMeta`, handles loading and `Investigation not found` honest not-found (no silent substitution), survives reload and server restart, frames via `GET /api/investigations/[id]/frames/[file]` with traversal check.

### 6. Evidence-Linked Assertion Builder
- **Location:** `src/lib/spec/builder.ts` — `SpecAssertionSchema` with `SelectorSchema` allowlist (`postal-error` only for M3.3), `MatcherSchema` enum (`toBeVisible`, `toBeHidden`, `toHaveText`), `expectedText` validation against `expectedBehaviour`, `frameId`/`timestamp` correspondence, `observationId` existence, duplicate ID rejection, path traversal rejection, hypothesis confirmation check, code injection rejection (`import`, `eval`, etc.).
- **API:** `POST /api/investigations/[id]/spec` with `AddAssertionSchema { observationId, matcher, expectedText?, selector? }`, validates via `validateAssertion`, compiles, saves; `DELETE /api/investigations/[id]/spec?assertionId=xxx` with confirmation.

### 7. Deterministic Playwright Spec Compiler
- **Location:** `src/lib/spec/compiler.ts` — `compileSpec()` uses predefined templates, fixed `ALLOWLISTED_URL = http://localhost:3000/demo/bug-01?variant=fixed`, `escapeStringLiteral` for safe string handling, `validateCompiledSource` rejects `eval`, `Function`, `require`, `process.`, etc., ensures identical input → identical output, saves to `test-results/investigations/<id>/spec-test.ts` and `spec.json` with provenance.

### 8. Read-Only Generated Source Preview
- **Component:** `src/components/investigation/SpecBuilder.tsx` — shows available observations with frame/timestamp, matcher select, expected text input, provenance, validation status, Add assertion, assertion list with provenance and Remove (with `confirm`), compiled preview in `pre` with `data-testid="spec-preview"` read-only, Copy button, "Preview only — generated specification is not executed by this runner." label, save persists via API, Light/Dark themed with tokens, desktop (aside) and mobile (bottom sheet) responsive.

### 9. Saved Assertions and Provenance
- **Storage:** `spec.json` with `SpecData { investigationId, assertions: SpecAssertion[], compiledSource, updatedAt }` and `spec-test.ts` — both validated and persisted via `saveSpec`, reloaded on detail page, provenance displayed per assertion.

## Security Constraints Preserved

- No execution of `spec-test.ts` — preview only, separate from `src/lib/runs/runner.ts` (real runner) and `src/lib/spec/compiler.ts` (template renderer)
- No arbitrary Playwright code — only allowlisted `postal-error` + 3 matchers, validated
- No arbitrary target URLs — `isAllowedUrl` + `startsWith /demo/bug-01`
- No exposure of `test-results/` — only via `GET /api/runs/[id]/artifacts/[file]` and `GET /api/investigations/[id]/frames/[file]` with traversal checks
- No access to another investigation's files — `getInvestigationDir` + `path.resolve` check
- No client-trusted bundle — server re-validates via `EvidenceBundleSchema` on POST
- Preserve M3.2 allowlist and artifact protections
