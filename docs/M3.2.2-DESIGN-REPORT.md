## Design System

### Reusable Token System — `src/app/globals.css`

Single source of truth for both themes, no duplicated styles across routes:

```css
:root (light): --canvas #ffffff, --surface #ffffff, --surface-elevated #f8f8f9, --border-muted rgba(0,0,0,0.08), --text-primary #111113, --text-secondary #6b6c72
[data-theme="dark"]: --canvas #08090A, --surface #0F1011, --surface-elevated #1A1C20, --border-muted rgba(255,255,255,0.08), --text-primary #F1F1F2, etc.
--accent #5E6AD2 (indigo, interaction/selection in both themes)
--red #ef4444 / #f87171, --green, --amber, --violet with muted variants
--shadow-sm/md, --border (hairline 1px)
```

All components reference `var(--canvas)`, `var(--surface)`, `var(--border-muted)`, `var(--accent)` etc — no hardcoded zinc/amber per component. Light is not inverted dark: both have intentionally layered surfaces (canvas → surface → elevated) with subtle grey structural borders in light, muted rgba in dark.

### Typography — Deploy-Safe Licensed Configuration

- **Layout:** `src/app/layout.tsx` uses `Inter` (next/font/google, variable, `display: swap`) as `--font-inter` for all UI, headings, body. `JetBrains_Mono` as `--font-mono` for timestamps, selectors, IDs, logs, code. Berkeley Mono noted as optional when licensed asset available — not committed.
- **Scale:** Main workspace heading 22px Inter 600 tracking -0.025em, section headings 13-15px Inter 500, body 13px Inter, secondary metadata 12px Inter, technical metadata 11px mono. Tight proportional tracking for larger headings only (`-0.02em` on h1/h2, not fixed -3px), restrained scale, hierarchy via weight/contrast/spacing.
- **Rule enforced:** Mono never for marketing, sans never for selectors — code references `font-mono` for all `data-testid`, `⟦00:01.8⟧`, `frame-00-00-8`.

### Dual Theme — Accessible, Persistent, No Flash

- **Toggle:** `src/components/ThemeToggle.tsx` `data-testid="theme-toggle"` with `aria-label="Switch to light/dark mode"` — indigo focus ring, hairline border, 28×28, placed in global TopBar on every route (investigations list, detail, demo buggy/fixed) for consistency.
- **Persistence:** `src/components/ThemeProvider.tsx` reads `localStorage('replayspec-theme')` on mount, falls back to `prefers-color-scheme`, writes on toggle. Persists across reloads and navigation (all 4 routes tested).
- **No Flash:** `layout.tsx` inline script `(function(){localStorage.getItem...})()` sets `data-theme` before hydration, verified via `document.documentElement.hasAttribute('data-theme')` immediately on load.
- **System Preference:** Listener on `matchMedia('(prefers-color-scheme: dark)')` change — respects system initial, updates when no stored preference.
- **Consistency:** Tested across `/investigations` → `/investigations/bug-01` → `/demo/bug-01?variant=buggy` → `/demo/bug-01?variant=fixed` and mobile 390×844 — all retain theme.

### C. /demo/bug-01?variant=buggy|fixed — MAISON Checkout Preserved, Credible in Both Themes

**Preserved MAISON identity:** Header `MAISON`, progress through Cart and Details, a clear `Demo · no payment` label, and cart icon. This is a local checkout validation demo; it does not place orders or collect payment.

**Credibility improvements for both themes:** Uses `var(--canvas)` for page, `var(--surface)` for card, `var(--border-muted)` hairline, `var(--text-primary)` for inputs with `focus:ring-[var(--accent)]`, order summary with hairline, not zinc-200 harsh outlines. Both variants visually understandable: buggy shows empty postal with no red error (hidden), fixed shows red `Postal code is required.` with `aria-invalid` — both verified in light and dark.

**Responsive:** Order summary collapses below form on mobile, header progress hides to Cart only, variant switcher remains accessible.

- **Avoided:** Oversized headings (now 22px not 24-28px max), large empty whitespace (reduced py-10 to py-6), decorative gradients (removed amber gradient banner, flat muted), too many coloured badges (now only verdict + variant), unnecessary shadows (only shadow-sm), thick borders (hairline rgba), generic dashboard patterns (no dashboard cards, just list + timeline).
- **Recording/frame/evidence dominate:** Timeline is primary, frame viewer is largest element, inspector is dense typography, not card wall.

## Remaining Design Limitations

- **@theme warning:** Tailwind v4 `@theme inline` still emits `Unknown at rule: @theme` in dev — not visual, no impact on production (postcss correctly generates `--color-*`).
- **Berkeley Mono:** Not bundled — licensed commercial font, using JetBrains Mono as fallback per spec ("Berkeley Mono may be used when valid licence and asset are available. Never commit unlicensed files.").
- **Dark scrollbar:** Uses `var(--border-strong)` thin, not fully Linear's custom scrollbar (OS-dependent).
- **FrameViewer video:** Still placeholder WebM via `test-results/runs`, not integrated live video scrub (M3.2 video capture preserved, but timeline is static frames).
- **Order summary images:** Emoji 🧥/👜 with border, not real product photos — M3.2.1 limitation carried forward, not redesigned with asset pipeline.
- **No custom illustration:** Investigation list empty state still text-only, no filmstrip→timeline illustration (deferred to M3.3).
